# 水晶之井 · Crystal Well

A nearly wordless desktop / landscape-mobile 3D brick breaker. A giant Eastern crystal dragon is sealed under eight **solid layers of crystal bricks**. Catch the returning ball with a circular shield above the well, collect rising magic bubbles, and break the seal to release the dragon.

## Play

The game is static: no account, API key, backend or build step. Serve the repository root over HTTP in a modern WebGL2 browser:

```bash
python3 -m http.server 8000
```

Open `http://localhost:8000`. Three.js `0.187.0` is pinned in the import map and loaded from jsDelivr; an initial internet connection is required. An offline distribution may vendor the same version and update the import map. Preserve `.openai/hosting.json` when deploying.

Move the mouse or drag a finger in the main view to move the shield. Click/touch-release or **Space** launches a held ball. **Esc** pauses/resumes; P also works. Arrows/WASD move the shield; R restarts. Portrait shows a rotating 3D phone prompt instead of a cramped game.

Normal shield contact rebounds immediately. Only the purple bind pickup enables capture. New-life serves and captured balls both wait for explicit release: cyan crystal petals mean a new ball, purple petals mean a captured ball. A pulsing sculpted launch symbol marks the held state. Missing a ball briefly leaves the shield empty before a replacement appears. There are **three lives**.

## Current version: v0.6 — matte dragon and lighter rendering

The approved external sculpt now has a matte body, mane, horns and beard; only source-space eye regions retain gloss. A further **30° nose-down rotation about the actual across-ear axis** is applied to both the rendered face and its sampled collision proxy. The cameras frame the scene slightly closer without changing shield controls.

The magical sea fills the visible ground plane instead of ending at a circular disk. Its visual radius is 256 units; collision remains confined to the original 9.72-unit well radius. The rim is **ten elongated, intergrown crystal segments** with irregular broad facets, replacing 26 separate pebbles.

The low-value refraction system is removed completely: no background capture target, no refractive brick selection, no physical transmission prepass and no three-bounce prism loop. Single-pass reflections and cheap tinted thickness keep the crystal appearance. Fully enclosed bricks stay in physics but are not drawn until exposed. Pixel density, three lives, score, bubbles, depth-colored ball and all model HUD controls are preserved.

See [v0.6 implementation/verification notes](docs/V06-MATTE-SEA-PERFORMANCE.md). Earlier visual revisions are historical, not current requirements.

## Implementation

`physics.js` is the deterministic collision kernel. Production uses `AdventureGame` in `gameplay.js` for lives, scoring, pickups and explicit serve/capture states. `refined-world.js` extends the existing instanced crystal renderer; `hud-3d.js` renders the model HUD with the same WebGL context. The external dragon remains the same 399,999-triangle sculpt; the ten rim segments share four lightweight materials, and bubbles/particles are pooled. Crystal optics are a stylized approximation, not per-crystal ray tracing.

```bash
npm run check
npm test
```

These require Node but no npm dependencies. CI additionally installs the pinned Three.js and Playwright packages, runs a Chromium WebGL smoke test, and uploads screenshots plus `browser-report.json` as `visual-smoke`. CI uses SwiftShader; its FPS is **not** a desktop or phone hardware benchmark. Real-device performance still needs testing.

## Assets

The dragon is **not authored by this repository**. Source: [Grab3D Chinese Dragon](https://grab3d.com/models/creatures/chinese-dragon/), CC0-1.0, with the publisher's AI-assisted origin retained in `assets/dragon/provenance.json`. The exact source GLB and license are checked in; runtime does not depend on the asset publisher. Model failure is explicit and blocks launch rather than reverting to the rejected generated dragon. `scripts/vendor-dragon.py` records the one-time import procedure.

Other game models, symbols and textures are generated by this repository. Three.js is a third-party MIT-licensed dependency. The detailed dragon mesh is separate from a coarse collision height field sampled from the actual imported sculpt. The software-renderer test screenshots are visual checks, not real-device performance benchmarks.
